# AIGate Eval

Самостоятельная проверка AIGate с готовой базой **639 проверок**: 374 строки с персональными/чувствительными данными и чистыми контролями, 265 строк для обнаружения промпт-инъекций. После клонирования ничего скачивать или генерировать не нужно. Нужен Python 3.9+, сторонние пакеты скрипту не требуются.

Полная инструкция — в [README.html](README.html): настройки, политика, метрики, конвертер открытых наборов, формат своих файлов. Откройте файл в браузере после клонирования.

## Быстрый старт

```bash
git clone https://github.com/aitalon/aigate-eval.git
cd aigate-eval
python3 aigate_eval.py datasets   # проверка базы офлайн, без токена и config.ini
cp config.example.ini config.ini   # укажите url AIGate и ключ приложения
python3 aigate_eval.py check       # проверка подключения и политики
python3 aigate_eval.py             # все проверки; отдельно: pii или injection
```

Обычный запуск берёт **все** встроенные `*.jsonl` из обеих папок. `--limit 5` берёт первые пять строк **каждого файла**; это smoke, а не репрезентативная выборка. `--only core` выбирает только инъекции из `core.jsonl` (с командой `injection`). Результаты — в `results/`.

## Готовая база

| Проверка | Состав |
|---|---|
| ПДн и чувствительные данные | 28 типов, 360 сущностей, 89 чистых контролей; RU/EN |
| Инъекции | 132 атаки, 133 безопасных текста; 13 семейств; RU/EN |
| Контексты | Тикеты, CRM, документы, JSON/CSV/XML/YAML, логи, код, Markdown, Unicode, повторения и границы строк |
| Атаки | Подмена ролей и инструкций, кража данных, злоупотребление инструментами, RAG, обфускация, подмена ответа и процесса, отравленные MCP-описания |

Новые кейсы — оригинальная синтетика; это диагностическая база, а не независимая часть исходного исследования. Значения документов/секретов вымышлены. Форматно валидный идентификатор не означает реальную принадлежность. Расширенные категории помечены `policy_dependent`: их защита зависит от активной политики. Данные не подгоняются под ответы демо. Подробности и контрольные суммы — в [описании базы](benchmarks/README.md).

`via = preflight` проверяет текст как пользовательский ввод без вызова LLM. Для модели инъекций должен быть включён канал `prompt`; по умолчанию сервер может проверять моделью только `tool_result` и `tool_description`. Для проверки этих каналов используйте `via = chat` с разрешённой `model`: запросы, которые пропустил шлюз, могут обращаться к LLM. Результаты режимов различаются.

В примере настроек `jobs = 1`: этого достаточно для последовательной проверки и соответствует детектору с одним обработчиком. Параллелизм повышайте по мощности своей установки. Для изолированного замера ПДн используйте отдельную интеграцию с нужными типами маскирования; блокирующие правила инъекций могут влиять на общий результат политики.

В отчётах есть решения по строкам, категории атак, языки, типы ПДн и SHA-256 исходных файлов. Ошибки API, неполное сканирование и ограничения не засчитываются как обнаружение. Код `1` означает неполный/ошибочный прогон; код `0` означает завершённое измерение, даже если найдены пропуски или ложные срабатывания.

Для ПДн сохранён исходный критерий «скрыто ≥50% букв/цифр» и отдельно добавлено полное скрытие букв/цифр. Цифры внутри новых служебных токенов AIGate не считаются сохранившимися исходными данными. Обе метрики используют сопоставление текстов и не доказывают невозможность восстановления значения.

Сопоставление с ранее выданным клиентам материалом, восемью открытыми наборами и ADR/AgentDojo — в [методике сравнения](docs/client-benchmark-contract.md). Опубликованные ранее проценты нельзя переносить на эту синтетику или текущую политику демо.
